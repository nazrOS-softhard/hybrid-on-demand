# Гибрид Разряд — мобильное приложение

Кроссплатформенное (iOS/Android/Web) приложение мобильной электрозаправки на **Expo (React
Native) + expo-router + TypeScript + Supabase**. Полностью рабочий продуктовый каркас: онбординг,
регистрация/авторизация, работа с личными автомобилями, весь флоу заказа зарядки (выбор
автомобиля → адрес → время → тариф → подтверждение → ожидание → зарядка → завершение), история
заказов, способы оплаты, поддержка (FAQ) и профиль.

Стек выбран под ваш рабочий процесс: полностью браузерный workflow без терминала — редактирование
через GitHub, сборка через **EAS Build** (облако), в том числе автоматически через GitHub Actions.

## Структура проекта

```
app/                      # Экраны (expo-router, файловая маршрутизация)
  index.tsx                — сплэш-экран + редирект
  onboarding.tsx            — онбординг 1–3
  (auth)/                   — регистрация, авторизация, восстановление пароля
  (app)/
    (tabs)/                 — Главная, История, Автомобили, Поддержка, Профиль
    order/                  — весь флоу заказа зарядки (8 экранов)
    cars/add.tsx             — добавление автомобиля
    profile/                 — личные данные, способы оплаты, настройки
src/
  components/               — переиспользуемые UI-компоненты
  hooks/                     — работа с Supabase (машины, заказы, тарифы, оплата)
  store/                     — Zustand: сессия/профиль, черновик заказа
  lib/supabase.ts            — клиент Supabase
  constants/theme.ts         — дизайн-токены (тёмная тема, как в макете)
supabase/schema.sql         — полная схема БД + RLS-политики + сиды тарифов
```

## 1. Настройка Supabase

1. Создайте проект на [supabase.com](https://supabase.com) (или используйте существующий).
2. Откройте **SQL Editor → New query**, вставьте содержимое `supabase/schema.sql` целиком и
   нажмите **Run**. Это создаст таблицы `profiles`, `cars`, `tariffs`, `orders`,
   `payment_methods`, включит RLS-политики (каждый видит только свои данные) и добавит 3 базовых
   тарифа.
3. В **Authentication → Providers** убедитесь, что включён Email/Password. На этапе разработки
   можно отключить подтверждение почты (**Authentication → Settings → Email confirmations**), 
   чтобы регистрация сразу открывала сессию.
4. В **Settings → API** скопируйте `Project URL` и `anon public` ключ.

## 2. Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

```
EXPO_PUBLIC_SUPABASE_URL=https://ваш-проект.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=ваш-anon-ключ
```

Для сборок EAS те же значения нужно продублировать в `eas.json` (поля `env` в каждом профиле) —
они уже подготовлены, просто замените плейсхолдеры.

## 3. Загрузка в GitHub

1. Создайте новый пустой репозиторий на GitHub (без README/gitignore — они уже есть в архиве).
2. Загрузите содержимое этого архива в репозиторий (drag-and-drop через веб-интерфейс GitHub —
   Add file → Upload files — работает полностью из браузера, терминал не нужен).

## 4. Сборка через Expo (EAS Build) — тоже без терминала

Вариант А — **сайт expo.dev**:
1. Зарегистрируйтесь / войдите на [expo.dev](https://expo.dev).
2. Создайте новый проект, привяжите к вашему GitHub-репозиторию (Projects → Import from GitHub).
3. В настройках проекта задайте переменные окружения `EXPO_PUBLIC_SUPABASE_URL` и
   `EXPO_PUBLIC_SUPABASE_ANON_KEY` (Project settings → Environment variables) — либо оставьте
   значения из `eas.json`.
4. Запустите сборку (Builds → Create a build) для Android (`.apk`/`.aab`) и/или iOS.

Вариант Б — **GitHub Actions** (уже настроен в `.github/workflows/eas-build.yml`):
1. Получите токен на expo.dev: **Account settings → Access tokens → Create token**.
2. В репозитории GitHub: **Settings → Secrets and variables → Actions → New repository secret**,
   имя `EXPO_TOKEN`, значение — токен.
3. Запустите workflow вручную: вкладка **Actions → EAS Build → Run workflow**, выберите профиль
   (`preview` — для APK на тест, `production` — релизная сборка) и платформу.
4. Ссылка на готовую сборку появится в панели [expo.dev](https://expo.dev) вашего проекта.

Перед первой сборкой один раз нужно связать проект с EAS — либо через сайт expo.dev при импорте
репозитория (он сам создаст `projectId` и обновит `app.json`), либо вручную заменив плейсхолдер
`extra.eas.projectId` в `app.json` значением, которое покажет expo.dev после создания проекта.

## 5. Локальная разработка (опционально)

Если когда-нибудь понадобится терминал:

```bash
npm install
npx expo install --fix   # подгонит версии пакетов под установленный SDK
npx expo start           # откроется QR-код для Expo Go / веб-превью
```

## Дизайн

Тёмная тема, синий/бирюзовый градиентный акцент — воспроизведена точно по референсному макету:
единая палитра и токены отступов/радиусов в `src/constants/theme.ts`, переиспользуемые
компоненты в `src/components/` (Button, Input, Card, ProgressRing и др.), чтобы все ~25 экранов
были визуально согласованы.

Карта на экранах выбора адреса и ожидания приезда — стилизованная SVG-заглушка (не требует
Google/Yandex Maps API ключа), чтобы проект собирался «из коробки» без дополнительных
credentials. При необходимости её легко заменить на `react-native-maps` или карту Яндекса —
компонент вынесен отдельно в `src/components/MapPreview.tsx`.

## Что реализовано

- Онбординг (3 экрана), регистрация, авторизация, восстановление пароля — Supabase Auth
- Профиль пользователя (таблица `profiles`, автосоздание триггером при регистрации)
- Мои автомобили: добавление, список, удаление, «основной» автомобиль
- Полный флоу заказа зарядки (8 экранов) с сохранением черновика между шагами (Zustand)
- Симуляция ожидания приезда и процесса зарядки с обновлением статуса заказа в реальном времени
- История заказов с фильтрами (все / завершённые / отменённые)
- Способы оплаты: карта / Apple Pay / Google Pay (демо-режим, без реального процессинга)
- Поддержка: FAQ-аккордеон, звонок/письмо в поддержку
- Настройки: уведомления, безопасность (UI), версия приложения

## Что стоит доработать перед продакшеном

- Подключить реальный платёжный провайдер (ЮKassa/Stripe/CloudPayments) вместо демо-сохранения
  номеров карт
- Заменить `MapPreview` на настоящую карту с геокодированием адресов
- Реальную диспетчеризацию станций вместо симулированного таймера на экранах ожидания/зарядки
  (например, через Supabase Realtime + серверную логику диспетчера)
- Push-уведомления (Expo Notifications) о статусе заказа
